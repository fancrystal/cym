# 本地商圈 Android App 方案（已确认）

日期：2026-11-11

## 目标

首版提供独立的安卓安装包，应用默认名为“本地商圈”，以 Android 原生壳加载现有 `https://cym.green` H5。后台仍通过 `https://admin.cym.green` 的浏览器访问。首版采用安装包自下载方式交付，暂不开发 iOS 或自动出款。

安卓包、服务器和数据库均独立于 mskj；应用展示和业务逻辑继续使用本项目的 H5 和 API。Android 包的建议包名为 `green.cym.app`，正式签名及包名在首次发布前固定并核对可用性。

## 已核对的现状

- mskj 的 `packages/android` 使用 Kotlin、Android WebView 和 ZXing，包含文件选择、返回键和扫码示例，可作为参考；现有实现还包含语音权限、旧域名和旧 token 桥接，不直接原样复制。
- 商圈 H5 已有 `cym-token` 登录状态、邀请码链接、团队收益、商品购买和提现；转账截图通过带鉴权的 API 获取，并以 `blob:` 链接打开原图。
- 本机已有 Android Studio、Java 21、Android SDK 34 和 36.1、Gradle 8.9 缓存；当前没有检测到连接的安卓设备。实际构建时先验证 Gradle、Android 插件及 SDK 的兼容性，必要时补装匹配版本。

## 首版范围

1. **启动和使用**：独立应用图标、启动页和 Android WebView，打开现有商圈 H5；适配状态栏、底部手势区、软键盘、窄屏和横竖屏。H5 更新经服务器发布后，用户重新进入页面即可获得更新；原生壳功能或权限发生变化仍需更新 APK。
2. **登录**：沿用当前 H5 的登录及 WebView 本地存储，不引入第二套 token；App 重启后在会话仍有效时保持登录，退出时清除当前账户状态。网页浏览器与 App 的登录状态互相独立。
3. **邀请和扫码**：在 App 内提供扫码入口，扫描商圈邀请二维码后校验域名和邀请码，并进入注册页面；从外部打开 `https://cym.green/#/login?transfer_invite=...` 时，保留完整链接与邀请码。通过 Android App Links 和域名验证支持系统直接打开 App；不同微信或其他扫码应用对外部链接的处理方式需实测，不能保证每种应用都能直接唤起。
4. **页面交互**：支持网页确认、提示和输入弹窗，安卓返回键先关闭当前弹层或返回上一页，再提供退出确认；断网或站点不可达显示重试页面。二维码复制及系统分享在目标手机上验证，必要时添加受限的原生分享能力。
5. **图片与截图**：用户提现记录中的缩略图和点击原图采用 App 内可关闭的图片查看器，使用当前 H5 已鉴权取得的图片，不将私有截图转换为公开链接。支持安全的系统文件选择能力，单选、多选及取消结果按网页需求返回；如未来要在 App 中打开后台，商品及转账截图上传也要覆盖测试。
6. **外部链接**：商圈域名在 App 内打开；其他网页通过系统浏览器处理。只对用户确认且安全的外部应用链接使用系统跳转，不为提现增加自动付款功能。
7. **更新**：首版提供固定下载页面和版本号，用户通过下载新版 APK 手动更新；签名一致时可覆盖安装并保留应用数据。网站内容更新通常无需重新安装，原生代码和权限变更必须重新打包。

## 安全与权限

- 正式环境仅使用 HTTPS；不关闭证书校验。限制 WebView 主页面导航，避免把应用内部能力暴露给不受信任网页；发布版关闭 WebView 调试。
- 扫码时按需请求相机权限；系统文件选择优先使用系统选择器，按实际功能申请权限。首版无需麦克风、通讯录、定位或后台通知权限。
- 不把用户密码、支付宝账号、订单信息或转账截图写入日志；不将私有截图、认证令牌或签名密钥提交 Git。
- App 使用独立签名密钥，不复用或覆盖 mskj 签名。签名文件及密码单独安全保存和备份，后续更新使用相同签名；正式包上传前核验签名与包名。

## H5 和服务器配合

- 对邀请链接处理补齐 App 已在前台、冷启动、未登录和已登录几种情况；保证扫码或外部链接不会丢失邀请码。
- 为转账截图增加站内全屏查看与关闭，避免依赖 WebView 对 `target="_blank"` 和 `blob:` 新窗口的默认行为。图片读取仍须使用原有用户授权接口。
- 验证 `confirm()`、`prompt()`、复制、`crypto.randomUUID()`、长页面滚动和键盘遮挡；根据实际 WebView 版本补充兼容处理。
- 配置 `https://cym.green/.well-known/assetlinks.json`，登记正式包名和签名证书指纹；验证服务端 HTTPS 直接返回、无跳转，并验证 App Links。该文件与服务器现有站点隔离部署。
- APK 下载页面应提供版本、大小、更新说明、签名校验信息及安装指引。正式对外分发前，核实并办理 APP 备案；已有网站备案可按主管部门要求补充 APP 信息，不应默认网站备案自动覆盖 App。

## 开发及验收计划

1. **工程与启动**：在本项目新增独立 Android 工程；核实构建版本，配置开发和正式域名、应用名、图标、版本号及签名，完成 Debug 包。
2. **核心适配**：实现 WebView、网络错误和返回处理，补充站内图片原图查看；确保登录、退出、商圈、团队、订单和提现与现有 H5 一致。
3. **邀请和文件**：实现扫码、邀请链接接收和系统分享；适配文件选择和必要的权限提示；配置并验证 App Links。
4. **自动测试和手机验证**：执行 Android 构建与关键原生逻辑测试，并在模拟器和至少一台真实手机上验证登录、扫码/链接注册、购买、订单图片、收益和提现记录原图、断网恢复、旋转屏幕、键盘、退出及覆盖安装；H5 和 API 的现有测试继续通过。
5. **发布**：生成并备份独立正式签名，签发 Release APK，核验包名/版本/签名并安装测试；确认备案与分发条件后发布下载页面。提供 APK 文件、版本说明、安装说明及后续更新方法。

## 不纳入首版

iOS、聊天与语音、自动支付宝转账、系统级消息推送、应用市场上架，以及离线下单。后续如需推送或市场分发，再单独确认方案和相应权限、备案与渠道要求。
